# Audit of the existing app (before the knee pathway build)

Step 1 of the build sequence in the master brief. This records what was actually working, what looked finished but wasn't, and what changed as a result. The audit was done by running the app, running its tests and reading the code, not by looking at screens.

## Scope audited

Routes (`src/app/App.tsx`), the local data model (`src/data/models.ts`, `store.ts`), the camera and pose path (`src/camera`, `src/engine`), the demo seed, the dependencies (`package.json`), and the Vercel configuration.

## Working at the time of the audit

| Area | State |
|---|---|
| Pose provider abstraction | Working. MediaPipe BlazePose Lite and Full run on-device, plus a labelled simulator. |
| Motion pipeline | Working and unit-tested. Pixel-space angles, confidence gating, One Euro / EMA / Kalman filters, orientation vote. |
| Rep state machine and Motion Mirror | Working. Counts only full reps (target → hold → return), pauses on tracking loss. |
| Calibration | Working, with a defect (see below). |
| Body map | Working. 4 views, zoom, multi-select, patient-perspective sides. |
| Red-flag triage, consent, local auth, audit log | Working, but local to the device only. |
| Clinician review with Accept / Reject / Repeat / Note | Working for single measurements. |
| Validation Mode and CSV export | Working. |
| Postgres schema | Present. It validated on Postgres 16. |

## Missing for the knee pathway

These were all built in this change:

- Symptom types, the drawn radiation path, and anatomy / side / type / location stored as separate fields.
- An adaptive history that keeps the original answers, and a clinician-amendable summary.
- A versioned safety questionnaire that stores question, answer, trigger, action and time per item.
- A clinician-editable test plan.
- Defined knee test protocols with quality gates, landmark replay, bilateral comparison and matched reassessment.
- The evidence map, the "Why?" panel, the reasoning states, the clinician impression, and the report (PDF / print / patient summary).
- Rehab prescription fields for progression and the pain-pause rule.

## Misleading or placeholder behaviour found, and the fix

| Finding | Why it misled | Fix |
|---|---|---|
| Calibration's landmark-confidence check used the **mean** visibility of the required landmarks. | One occluded joint (for example the knee behind a chair leg) could still pass while the other joints were clear. | Every required landmark must now meet the threshold on its own. The check names the joints that fail. There is a unit test. |
| Calibration always judged distance by **vertical** body extent. | For a patient lying down (heel slide) it asked them to "move closer" forever, so the capture could never start. | Protocols declare `extentAxis: 'horizontal'` for supine tests. Unit-tested and browser-verified. |
| Demo measurements were typed-in numbers. | They looked like engine output but no engine had produced them. | All demo captures and sessions are now generated by running the real protocol engine and exercise runner on synthetic landmarks. They carry `source: simulated_demo` and a DEMO badge. |
| Demo patients had realistic fictional names. | The brief forbids identifying-looking data in seeds. | They are now pseudonymous codes ("Demo patient DP-01/02/03"). The only named person is the clinician, Dheepika, whose practice this is. A test (`demo.test.ts`) checks this. |
| The body map had two separate rotate controls. | They were duplicates and confusing on small screens. | Now there is one segmented view control, plus swipe and arrow keys. |
| A condition could show as "supportive" on range-of-motion facts alone (e.g. post-operative stiffness without surgery). | It overstated the reasoning. | Rules can declare a **defining feature**. Without it the state cannot be supportive, and the missing feature is listed. There is a unit test. |
| Sit-to-stand rise time was measured from the cycle boundary (61°). | Rise time came out at about half the true value. | Rise onset is now detected by leaving the seated plateau by more than 5°. Tested against an analytically derived reference. |
| The patient's "View report" link only looked at the newest assessment. | After starting a reassessment, the approved baseline report vanished. | It now links the most recent clinician-approved report. |

## Screenshot privacy

The brief's reference screenshots contain names, contact details and camera images of real people. **None of this was copied** into code, fixtures, seed data, tests or documentation. The only person named in the product is the clinician the product is built for, and she can be renamed in Settings.
